## 1. TỔNG QUAN HIỆN TRẠNG KIẾN TRÚC DỰ ÁN GỐC (PHP & JS SPA)

Qua rà soát toàn bộ mã nguồn tại thư mục gốc (`app/`, `database/`, `public/`, `js/`, `css/`, `index.html`), hệ thống hiện tại đang tồn tại **hai luồng kiến trúc song song (Dual/Split Architecture)** chưa được hợp nhất hoàn chỉnh:

1. **Luồng 1 – Hệ thống PHP MVC Thuần (Server-Side Rendering - SSR) theo chuẩn HUHA HRM**:
   - **Entry point**: `public/index.php` $\rightarrow$ `App\Core\App` (`app/core/App.php`).
   - **Controllers chính** (không dùng namespace): `AuthController`, `DashboardController`, `EmployeeController`, `AttendanceController`, `PayrollController`, `RecruitmentController`, `TrainingController`, `TransferController`, `RewardDisciplineController`, `ReportController`, `RoleController`, `AiExpertController`.
   - **Database**: Sử dụng schema tiếng Việt `vinamilk_hrm` (`database/vinamilk_hrm.sql`) gồm **16 bảng gốc** (`dm_donvi`, `dm_chucvu`, `dm_ngach`, `dm_trinhdo`, `dm_ktkl`, `nhansu`, `qt_congtac`, `qt_bonhiem`, `qt_luong`, `qt_daotao`, `qt_ktkl`, `qt_thuyenchuyen`, `chamcong`, `bangluong`, `tintuyendung`, `hoso_ungvien`, `ketqua_phongvan`, `roles`, `users`, `permissions`, `role_permissions`, `menu_items` — tổng cộng 22 bảng trong file SQL) và **5 bảng tự sinh lúc chạy (Runtime DDL)** bên trong hàm `__construct()` của Model (`lich_su_truy_cap`, `bang_cham_cong_chitiet`, `don_xin_nghi`, `de_xuat_tuyen_dung`, `dm_khoa_dao_tao`, `ai_recommendations`).
2. **Luồng 2 – Hệ thống API Prototype (`App\Controllers\*`) & SPA Mock (`index.html` + `js/modules/*`)**:
   - **Controllers API** (dùng namespace `App\Controllers`): `DepartmentController`, `KpiController`, `EmployeeDashboardController`, `ApiAnalyticsController`, `ApiEmployeeController`, `ApiEssController`, `ApiOnboardingController`, `ApiSecurityController`.
   - **Database & Mock Data**: Truy vấn vào các bảng tiếng Anh (`departments`, `employees`, `contracts`, `kpi_metrics`, `attendance_records`, `leave_requests`) nằm rải rác ở `database/schema.sql`, `database/employees.sql`, `database/contracts.sql` (database `vinamilk_hris`), hoặc dùng dữ liệu tĩnh (hard-coded JS objects) trong `js/data/*.js` (`assets_data.js`, `categories_data.js`, `kpi_data.js`, `leave_data.js`, `employees.js`, `payroll.js`, `recruitment.js`, `attendance.js`).

> [!WARNING]
> **Rủi ro kiến trúc nghiêm trọng nhất hiện tại**: Hai luồng trên xung đột trực tiếp về cấu trúc CSDL (`vinamilk_hrm` vs `vinamilk_hris`), cơ chế Session/CSRF (`VNM_HRM_SESSID` + `vnm_csrf_token` vs `PHPSESSID` + `csrf_token`), và nhiều API Controller gọi các phương thức không hề tồn tại trong `Database` hoặc `EmployeeModel`, dẫn đến lỗi `Fatal Error` khi gọi thực tế.

## 3. SO SÁNH VỚI CHUẨN HRM DOANH NGHIỆP & PHÂN LOẠI MoSCoW

Để nâng cấp **Vinamilk HRM** lên tầm vóc một **Enterprise HRIS/HCM** thực thụ (tiệm cận SAP SuccessFactors, Workday, MISA AMIS HRM, Base HRM, 1Office) trên nền tảng **ASP.NET Core 8 Clean Architecture**, dưới đây là bảng phân tích khoảng trống chức năng (Gap Analysis) được phân loại theo phương pháp **MoSCoW**:
- **M (Must have)**: Bắt buộc phải có trong hệ thống .NET 8 mới (đảm bảo toàn vẹn nghiệp vụ hiện có + chuẩn hóa kiến trúc + pháp lý lao động VN).
- **S (Should have)**: Nên có để hoàn thiện trải nghiệm HRM chuyên nghiệp (tự động hóa, workflow, biểu đồ nâng cao, thông báo realtime).
- **C (Could have)**: Có thể bổ sung để tạo lợi thế cạnh tranh (AI RAG, 360° Feedback, PWA, tự cấu hình công thức nâng cao).
